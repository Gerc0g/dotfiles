# WikiPedik: неиспользованная мощь подхода

Снимок на 2026-06-11, после восстановления цикла памяти (см. историю фиксов в
git log: worktree-симлинки, hot.md, health-checks, autocommit).

## Что уже работает (страховочный минимум)

Замкнутый цикл: захват (`lesson-append` → `_inbox.md`) → курация (`wiki sync` /
`inbox-drain`) → эскалация (`wiki synthesize` → `product/shared/`) → возврат в
работу (`hot.md` через SessionStart-хуки). Поломки склейки видны сразу: launch
health-check, tmux-бейдж, предупреждения в чате агента.

## Неиспользованные возможности

По убыванию ценности.

### 1. Чтение — только верхушка (hot.md, ~50 строк)

Авто-инжект — 2-3 урока и несколько готч. Полные `lessons.md`,
`debugging-stories.md`, product-паттерны лежат мёртвым грузом. Skill
`wiki-context-pack` (выборка памяти под задачу: rg по ключевым словам, индексы,
shared-паттерны) установлен, но вызывается только по доброй воле агента.

Идея: в plan-pane при `launch` инструктировать агента начинать нетривиальную
задачу с `wiki-context-pack`; либо включить вызов в hot.md-чекпойнт.

### 2. `agent-history-ingest` ни разу не запускался

165+ JSONL-сессий codex/claude, включая весь июнь 2026, когда захват был
сломан. В транскриптах — решённые баги, проваленные подходы, root causes,
которые никуда не записались. Skill умеет дельта-трекинг (что уже заингещено).

Идея: разовый backfill-прогон по июню из кураторской панели, затем
периодический (раз в 1-2 недели) проход по свежим сессиям.

### 3. Уроки умирают вместе с артефактами

Oracle-ответы (second-model review — концентрат инсайтов) живут в
`.agents/oracle/` внутри worktree и удаляются при cleanup. Логи test-tui — там
же.

Идея: перед удалением worktree выжимать из `.agents/oracle/*.md` уроки в
`_inbox.md` (или хотя бы перемещать ответы в вольт).

### 4. Сам dotfiles не подключён к памяти

Платформенные уроки (TCC у фоновых процессов, worktree не наследует untracked,
LLM-куратор пропускает фазы — нужен детерминированный fallback) записать
некуда: у dotfiles нет `docs/knowledge`. Платформа учит всех, кроме себя.

Идея: bootstrap dotfiles в вольт (отдельный scope вне company-неймспейсов,
например `20-projects/platform/`), записать накопленные уроки.

### 5. `open-questions.md` как очередь исследований пустует

По дизайну — задачи «разобраться перед следующей миграцией». Агенты могли бы
подхватывать их, когда касаются соответствующей подсистемы. Сейчас файлы
пустые, в plan-флоу не участвуют.

### 6. Верх лестницы promotion не работает

- `wiki lint` ни разу не запускался: нет борьбы со стейлом, противоречиями,
  просроченными `Last verified`.
- Promotion урока в ADR ни разу не происходил.
- Company-уровень (`shared/cross-product-lessons.md`) пустой.
- Rejected-записи инбокса должны тюнить фильтр `lesson-append` (заметка есть в
  skill inbox-drain), механизма обратной связи нет.

Идея-минимум: привычка `wiki lint <co>/<prod>` раз в месяц; health-check в
launch уже умеет показывать возраст hot.md — можно добавить возраст последнего
lint.

### 7. `10-wiki`-слой живёт отдельно от проектной памяти

Research-знания (источники, синтезы по Karpathy-паттерну) не линкуются с
проектными уроками, хотя формат один — markdown + wikilinks. Урок из
production мог бы ссылаться на статью, из которой взят подход, и наоборот.

## Рекомендованный порядок

| # | Шаг | Усилия | Эффект |
|---|---|---|---|
| 1 | History-ingest backfill июня | запуск готового skill | вернуть месяц потерянных уроков |
| 2 | Bootstrap dotfiles + записать платформенные уроки | ~10 мин | платформа учится на себе |
| 3 | Context-pack в launch-флоу | спроектировать + внедрить | глубокое чтение по умолчанию |
| 4 | Oracle-ответы → inbox перед cleanup | небольшой скрипт | инсайты не теряются |
| 5 | Ежемесячный lint + возраст в health-check | привычка + пара строк | защита от стейла |
| 6 | open-questions в plan-флоу | конвенция в AGENTS.md | очередь исследований оживает |
| 7 | Линковка 10-wiki ↔ project memory | кураторская практика | связное знание |
