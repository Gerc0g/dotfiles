# WikiPedik: шпаргалка пользователя

Минимум для постоянной работы с памятью. Полный реестр: `? wiki` / COMMANDS.md.
В wikipedik-tmux есть панель-меню (`wiki-menu`) — все эти действия по цифрам.

## 4 команды (90% использования)

```
wiki sync <scope>        # разобрать накопленное (neurodesk/agents, _platform)
wiki synthesize <scope>  # поднять повторы в паттерны/правила
wiki rules-sync [scope]  # разнести подтверждённые правила по репо
wiki-git push            # отправить вольт на GitHub
```

## 3 рефлекса (система сама заговорит)

1. `ℹ inbox N candidate — пора wiki sync` в SessionStart-контексте → запусти sync.
2. `⚠ wiki memory: не подключена` → `wiki bootstrap <co> <prod>`.
3. Куратор предлагает правило → вопрос себе: «обязан ли это соблюдать каждый
   агент?» → да/нет. После «да»: `wiki rules-sync`.

## 3 принципа (чтобы не сломать)

1. Новое знание входит через агента («запиши урок» в чат) — не правкой
   curated-страниц руками: иначе мимо дедупа, citations, evolution и hot.md.
2. Задачи завершать через `hq finish`; планы задач — коммитить в
   `docs/epics/` с веткой (сейф — страховка, не workflow).
3. Push вольта только руками; локальные коммиты копятся сами.

## 2 факта (понимать, что происходит)

1. hot.md — то, что агент знает на старте; остальное он дочитывает сам или
   получает правилом при касании файлов. Агент «не помнит» = не прошло sync.
2. Всё — markdown в `~/Desktop/WikiPedik/dev/20-projects/` под git: Obsidian
   для чтения — можно, потерять — нельзя.

## Редкое (по нуджам из SessionStart-хуков)

- `wiki lint <scope>` — раз в месяц, протухание/противоречия.
- history-ingest — раз в 2 недели, в чат куратора:
  `Use skill agent-history-ingest. --source all. Обработай новые дайджесты.`
  (перед этим `agent-session-digest.py --since <дата>`).
