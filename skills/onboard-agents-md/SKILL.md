# Onboard AGENTS.md

Interactive filler for TODO placeholders generated by `new-company` / `new-project`.

## Detect level (do this first)

Look at files in current working directory:

| Found | Level | Reference file to read |
|---|---|---|
| `.company-config` | Company | `questions/company.md` |
| `.product-config` | Product | `questions/product.md` |
| `.git/` (and no configs above) | Repo | `questions/repo.md` |

If `AGENTS.md` not found in cwd → STOP, tell user:
> "AGENTS.md не найден. Сначала запусти `new-company <slug> ...` или `new-project <co> <prod> ...`, потом возвращайся ко мне."

## Workflow

1. **Detect level** (see above), read corresponding `questions/<level>.md` file.
2. **Scan TODOs**: `grep -nE '(^|>)\s*TODO|<!-- TODO:' AGENTS.md` — счёт + локации.
3. **Show plan**: tell user how many TODOs found and that we walk through one at a time.
4. **Iterate**:
   - Ask ONE question per message (Vincent's brainstorm pattern)
   - Use multiple choice when obvious options exist (Yes/No, picklist)
   - Use open question when subjective (names, URLs, free text)
   - Apply edit to AGENTS.md **immediately** after each answer
   - Show changed line briefly: "✓ Updated: `Network: VPN required`"
5. **Closure**:
   - `grep -c TODO AGENTS.md` — count remaining
   - If 0 → "All TODOs resolved. Want me to git status + suggest commit?"
   - If >0 → list which ones left + suggest "type `done` to finalize anyway"
   - Show `git diff AGENTS.md` summary
   - Suggest commit message (Conventional Commits, Russian description per PLATFORM.md): `chore(<slug>): заполнить AGENTS.md TODO`
   - **NEVER `git commit` without explicit user ask.**

## User controls during walkthrough

- `skip` — leave current TODO as-is, move to next
- `back` — revisit previous TODO
- `done` — finalize, stop walking through remaining TODOs
- `pause` — save progress, stop session; resume later by re-invoking skill

## Rules

- ONE question per message. Never batch.
- Apply edits atomically (save after each answer). User can `pause` and not lose progress.
- Only edit `./AGENTS.md`. Never touch other files.
- Use `Edit` tool with exact string match, never overwrite the whole file.
- After all TODOs filled — verify by grep that `TODO` count = 0 (or user-acknowledged remaining).
- For repo-level: prefer auto-fill via codex bootstrap prompt (see `questions/repo.md`) before asking user. User answers only what code can't reveal (non-obvious patterns, repo-specific dangers).

## Why this approach

- **Progressive disclosure**: detailed question lists live in `questions/<level>.md`, loaded only when relevant level detected. Keeps SKILL.md small (~50 lines) so frontmatter routing is fast.
- **One question per turn**: Vincent's pattern (`fsck.com/blog/2025/10/05`) — keeps user engaged, reduces cognitive load, avoids batched answers that mix decisions.
- **Atomic edits**: each TODO resolved in one Edit call. User can interrupt anytime.
- **No commit automation**: respects PLATFORM.md rule "NEVER `git commit` without explicit user ask".
